## 摘要
昂贵优化任务在现实应用中普遍存在，需要高度专业的求解器。尽管LLM驱动的自动求解器生成显示出潜力，但当前范式在处理昂贵优化时面临三个关键问题：因领域知识不足导致的事实幻觉、在改进过程中频繁破坏先前建立的局部最优结构，以及在训练实例上执行带来的过高评估成本和受限的泛化能力。为解决这些问题，我们引入了AutoSG，这是一个完全自动化的流程，直接将自然语言提示转化为可执行的定制求解器。AutoSG具有三项核心创新：一个检索增强的求解器生成模块，严格将代码基于已验证的文献；一个单步自改进算子，在保留关键结构组件的同时引入任务特定改进；以及一个基于无实例的Elo评估机制，由LLM作为裁判快速建立全局排名。在多种昂贵优化任务上的广泛评估表明，AutoSG显著优于人工设计的最先进框架和现有的LLM生成求解器。

## Abstract
Expensive optimization tasks are ubiquitous in real-world applications, demanding highly specialized solvers. While LLM-driven automated solver generation shows promise, current paradigms face three critical issues when tackling expensive optimization: factual hallucinations due to deficient domain knowledge, the frequent dismantling of previously established locally optimal structures during refinement, and the prohibitive evaluation costs alongside restricted generalization caused by executing on training instances. To address these issues, we introduce AutoSG, a fully automated workflow directly translating natural language prompts into executable customized solvers. AutoSG features three core innovations: a retrieval-augmented solver generation module strictly grounding code in verified literature; a one-step self-refinement operator introducing task-specific improvements while preserving critical structural components; and an instance-free Elo-based LLM-as-a-Judge evaluation mechanism rapidly establishing global rankings. Extensive evaluations across diverse expensive optimization tasks confirm AutoSG significantly outperforms human-designed state-of-the-art frameworks and existing LLM-generated solvers.

## 2. 方法论：核心思想、关键技术细节

AutoSG包含三个核心模块，模拟人类专家“文献回顾→复现代码→精细调优”的工作流程。

### 2.1 检索增强求解器生成（RAG-based Solver Generation）
- **检索阶段**：LLM将任务提示重写为K=8个多样化搜索查询（包括宽泛查询和精确查询），同时通过API从OpenAlex和arXiv学术数据库检索论文。对每查询召回Top-30（OpenAlex）和Top-10（arXiv）论文，经去重、按年份排序后合并为N=40候选池。LLM基于元数据（标题、摘要、引用、期刊）对这些候选论文进行重排序，选出最相关的一篇论文，并提取其全文PDF内容D<sub>pdf</sub>。
- **求解器生成阶段**：采用两阶段生成管道：
  - **第一阶段**：LLM作为忠实复现器，基于可扩展代码模板T<sub>code</sub>（支持贝叶斯优化和代理辅助求解器）和检索到的文献D<sub>pdf</sub>，生成初步求解器S<sub>pre</sub>，并强制要求标注关键组件（P<sub>imp</sub>）。
  - **第二阶段**：LLM将S<sub>pre</sub>与文献中的伪代码、公式和超参数严格交叉验证，消除微观实现偏差，生成初始高质量求解器S<sub>init</sub>。

### 2.2 单步自精炼算子（One-Step Solver Self-Refinement）
- 核心思想：S<sub>init</sub>已经基于SOTA文献，处于算法搜索空间的局部最优附近，多步迭代进化不仅计算冗余，还容易破坏原有数学结构。
- 操作：LLM逆向工程S<sub>init</sub>生成语义代码描述D<sub>init</sub>，然后采用“学习-改进”范式（P<sub>refine</sub>），在保留关键组件（# IMPORTANT COMPONENT）不变的前提下，针对目标任务P<sub>task</sub>引入最小化的任务特定改进，直接生成C=10个候选求解器{S<sub>L1</sub>,…,S<sub>LC</sub>}。

### 2.3 基于Elo的LLM作为裁判（LLM-as-a-Judge）评估机制
- 目标：完全避免在昂贵实例上实际执行，实现无实例评估。
- 方法：采用动态更新的Elo评分系统进行多轮成对比较。每对求解器比较时，LLM根据裁判提示P<sub>judge</sub>（动态整合P<sub>task</sub>任务约束）判决胜者。Elo评分初始化为1500，偏差rd=350。
- 智能配对锦标赛：两阶段策略。
  - 阶段1：每个求解器至少配对T<sub>init</sub>=3次，优先匹配总比赛次数最少的对。
  - 阶段2：每个求解器达到T<sub>total</sub>=6次，优先考虑评分接近且比赛次数少对（使用组合启发式）。
  - 主动修剪：若两求解器评分差>Δ<sub>max</sub>=400且95%置信区间不重叠，则跳过匹配。
- 最终选取Elo评分最高的求解器作为最优解S*。
